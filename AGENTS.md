# CLAUDE.md -- Maxima Computer Algebra System

For AI agents working in this repository. What is here was checked against the
tree rather than copied from a README; hold anything you add to the same
standard. Where an in-repo README disagrees with the tree, the tree wins (sec.
16).

**Locating things.** Citations give file + construct name, never a line number:
lines drift within a release. Use `grep -n 'defun <name>'`, or `grep -F` on a
quoted comment.

## 1. What this is

General-purpose CAS in **Common Lisp**, from MIT's Macsyma (1970s). GPL
(`COPYING`, `AUTHORS`). Old and layered -- MIT-era Maclisp, 1980s UT-Austin,
modern additions; match the file you edit.

- Version: `AC_INIT([maxima], [<version>])` in `configure.ac`, but `configure`
  overwrites it from `git describe --dirty`, hyphens to underscores, wherever
  git can describe a tag.
- **Upstream is SourceForge** (`git.code.sf.net/p/maxima/code`).
  **`github.com/calyau/maxima` is a pure mirror**: commits, branches and PRs
  pushed there are overwritten on the next sync. Only SourceForge lands changes;
  a green GitHub branch is not work delivered.

## 2. Build

Prerequisites: **SBCL, Maxima's preferred Lisp** -- use it unless you have a
reason not to (`README-lisps.md` covers the rest, and their quirks) -- and
texinfo's `makeinfo`.

```sh
sh bootstrap            # only if ./configure is absent (a git checkout)
./configure --enable-sbcl
make
```

`-j` buys nothing on the Lisp build unless you configured several Lisps (it does
parallelise `doc/`): automake walks `SUBDIRS` in a serial shell loop, and each
core is one target whose recipe feeds the whole system to the Lisp -- a compile
pass, then a load-and-dump pass (`src/<lisp>-depends.mk` just lists every source
as a prerequisite of it). What gets recompiled is decided in that image by
`defsystem`, from the `:depends-on` graph in `src/maxima.system` -- so an edit
low in that graph, such as `src/simp.lisp`, costs far more than one at the
leaves. Prefer sec. 4's no-rebuild loop. `make install` is not needed --
`./maxima-local` runs the fresh image:

```sh
./maxima-local --version                                  # -> Maxima <version>
./maxima-local --no-init --batch-string='build_info();'   # which SBCL am I on?
```

**`makeinfo` is hard-required**: `enable_build_docs` defaults true
(`configure.ac`), so without it `./configure` **aborts**. Building
`--disable-build-docs` loses `?`/`??` help and prints
`WARNING: Maxima is unable to set up the help system.` at **every** startup
(`src/cl-info.lisp`, missing `doc/info/maxima-index.lisp`) -- noise in every
batch capture. `gnuplot` matters only for plots at runtime. An older or
less-used Lisp runs Maxima fine but can shift a numeric result the suite checks
(sec. 5).

### Two output directories

`src/binary-<lisp>/` holds the **build**: `maxima.core` plus a `.fasl` per
compiled source. Per Lisp, but **not** per Lisp *version* -- which is why a new
SBCL version needs `make clean` (sec. 15).
`binary/<version>/<lisp>/<lisp-version>/` (underscores, not dots) is the
**runtime** objdir `*maxima-objdir*`: fasls compiled from `share/` on demand --
created lazily, so it is absent until something compiles. `./maxima-local -d`
prints every resolved directory.

A build leaves `git status` clean.

### How the build works

`make` compiles **no** Lisp: it generates wrapper scripts, then shells out to
the Lisp, which loads `lisp-utils/defsystem.lisp` and runs `mk:defsystem` over
**`src/maxima.system`**.

- `src/maxima.system`: every source file in dependency order, in `:module`s.
- **Order matters** -- `defsystem` loads as it compiles, so macro modules
  precede users (`src/ratmac.lisp` CRE accessor macros before `p-var`/`p-lc`/...
  users).
- `src/Makefile.am` holds the build, dist and install rules -- but not the
  build's file list, which is `maxima.system`'s job.
- **Not** ASDF, despite the comment atop `src/Makefile.am`; `src/Readme.md`
  describes the `defsystem` build correctly. `src/maxima.asd` is a separate
  secondary path.
- `src/<lisp>-depends.mk` is **generated by `make`** (`sbcl-depends.mk` rule in
  `src/Makefile.am`, via `lisp-utils/make-depends.lisp`), gitignored, in
  `CLEANFILES`, one per configured Lisp. Never hand-edit: regenerated whenever
  `maxima.system`, the `Makefile` or any `*.lisp` changes.

`Makefile` is generated -- **always edit `Makefile.am`**.

### configure options

`./configure --help` lists every option; the `--enable-<lisp>` flags combine.
`--with-<lisp>=<prog>` names an explicit executable, absolute path or PATH name
(ABCL instead takes `--with-abcl-jar=<jarfile>`); an
`sbcl executable "..." not found in PATH` warning always means configure did not
find it, and the build will fail. Out-of-tree (VPATH) builds work.
`README-lisps.md`'s per-Lisp caveats are about how the *Lisp* was built, not
about Maxima's configure: GCL must itself be built `--enable-ansi`; ECL must be
built with its C compiler (never `--with-cmp=no`); CLISP slow but frugal; ABCL
slowest.

## 3. Running Maxima

`./maxima-local [options]` (`src/init-cl.lisp`). The options that matter:

- `--batch-string='<expr>;'` -- eval Maxima code, exit. The workhorse.
- `--no-init` -- skip `maxima-init.mac`/`maxima-init.lisp`. **Always in tests**,
  else results depend on the dev's machine.
- `-q`/`--quiet` -- suppress the banner. Safe everywhere, tests included.
- `--very-quiet` -- banner **plus** `*display-labels-p*`, `*verify-html-index*`
  and `*warn-deprecated-defmvar-options*` -> nil, and `--very-very-quiet` adds
  `TTYOFF` (use explicit `format` output). **Both drop the `(%i)`/`(%o)` labels
  and hide sec. 10's deprecation warnings. Never for tests (sec. 5).**
- `-Q`/`--quit-on-error` -- exit 1 on a **Maxima** error. Not Lisp errors
  (below).

`--help` lists the rest (`-b <file>` to batch a `.mac`, `--batch-lisp`, `-p` to
preload, ...).

### Four traps

**1. `-Q` misses Lisp errors.** They print
`Maxima encountered a Lisp error: ...`, **auto-continue**, and exit 0 even under
`-Q`:

```sh
./maxima-local --no-init -Q --batch-string='?car(5); 2+2;'   # exit 0 (Lisp err)
./maxima-local --no-init -Q --batch-string='1/0; 2+2;'      # exit 1 (Maxima)
```

A broken `src/` edit gives the first kind, so `-Q` alone is no CI gate -- also
grep stdout for `Maxima encountered a Lisp error`.

**2. Auto-continue poisons the rest of the batch.** A failed assignment leaves
the *old* binding; everything after computes confidently wrong answers. Run each
risky probe in its own process.

**3. `:lisp` eats the rest of the LINE**, not one form. `dbm-read`
(`src/mdebug.lisp`) strips a trailing `;`, wraps the whole remainder in parens
and reads it; `lisp-eval` runs the lot as one `progn`. Trailing Maxima code is
therefore evaluated as *Lisp*, normally a loud and unrelated error, while a
*mid*-line `;` comments out the closing paren:

```sh
--batch-string='5+5; :lisp (print 99) 7+7;'   # 10, 99, |7+7| is unbound
--batch-string=$':lisp (print 1)\n2+2;'       # 1, then 4  (correct)
```

Put `:lisp` on its own line, or last in the string.

**4. Some inputs never terminate**, and nothing in the batch stops one: it runs
until you kill it, filling the disk if it prints. Always
`timeout 120 ./maxima-local ...`.

### Internals

`:lisp <form>` evaluates Lisp. `?name` is the Lisp symbol `NAME` (`?car` is
`CAR`) -- how you reach a helper with no `$` prefix, since a plain Maxima `foo`
already *is* `$FOO`; backslash-escape anything Maxima's reader would take as an
operator, as in `?\*debug\-integrate\*`. `#$<expr>$` reads Maxima syntax from
Lisp.

**Two different `errcatch`es.** At Maxima level it returns `[value]` on success
and `[]` on error, and still **prints** the message; with several arguments it
returns only the last value, stopping at the first error (`errcatch(5, 5^2)` is
`[25]`).

The Lisp macro (`src/errset.lisp`) instead returns `(value)` or **NIL**, so it
is a fine truth value -- but `(car (errcatch form))` cannot distinguish a
NIL-valued success from a failure.

**Capturing output for parsing: set `display2d:false` first.** The default 2-D
display is multi-line box art and cannot be re-read; with it off you get one
re-parseable line (`string()`/`grind()` do the same for one expression):

```
display2d:false$ diff(sin(x)/x,x);   =>  cos(x)/x-sin(x)/x^2
```

**Interactive prompts eat the next statement**: `asksign`/`askinteger`/`read`
take it as their answer. `retrieve` reads it with `mread-noprompt`, so it needs
its own `;`/`$` but may sit on the same line (`asksign(a); pos; 2+2;` works). A
mid-script `asksign` silently eats your next expression and shifts the rest.
Exhausting input gives `RETRIEVE: End of file encountered.` -- a useful signal
the code asked more than expected. `is(a>0)` does **not** ask; it returns
`unknown`.

Most `MAXIMA_*` env vars are read by `set-pathnames` (`src/init-cl.lisp`); the
*internal* Lisp directory variables are documented in
`doc/implementation/dir_vars.txt`.

## 4. The edit-test loop

### Redefine at runtime instead of rebuilding

`:lisp (load "variant.lisp")` is **compiled** by SBCL, not interpreted, so you
can A/B a changed function inside one process:

```sh
./maxima-local --no-init --batch-string=$':lisp (load "variant.lisp")\nmy_test;'
```

Use it to **instrument** (count how often a branch fires over a whole suite run,
touching no source file), to **prototype** a fix before editing, and to
**baseline** it -- redefine your new helpers to no-ops and re-run for a real
before/after out of one build.

**Redefine the function on the call path**, often not the one named after the
user-visible operator:

```lisp
(get '%foo 'operators)   ; the simplifier for %foo
(get '$foo 'impl-name)   ; defmfun $foo makes FOO-IMPL -- the body is there
(get '$li  'specsimp)    ; subscripted functions like li[s](x)
```

Redefining `$foo` when a simplifier owns the operator does nothing, and looks
exactly like your fix not working. `FOO-IMPL` names are generated, so they
appear in no source file -- use `grep -rE 'defmfun \(?\$foo' src/`, since the
option-list form is `(defmfun ($foo ...) ...)`. Exception: a function declaimed
`inline` is inlined into its callers, so redefinition won't take -- such
declaims cluster in `src/mutils.lisp` (`mnump`, `ratnump`, `mplusp`, `mexptp`,
...), plus `defmfun ... :inline-impl t`. Ask the image:
`:lisp (sb-int:info :function :inlinep 'mnump)` -> `INLINE`.

Instrument with plain Lisp `format`/`print`: a Maxima-level display or string
function called from a hook in simplifier or limit code re-enters the code you
are instrumenting.

**Print to `*debug-io*`, not `*standard-output*`.** `run_testsuite` rebinds
`*standard-output*` per problem to a throwaway string stream (`test-batch` in
`src/mload.lisp`, restored in an `unwind-protect`) to keep incidental output out
of the log -- pass/fail is `batch-equal-check` on the returned *value*, and the
captured text resurfaces only in a failure report or under `display_all`. A
`format t` from an instrumented function is therefore swallowed, looking exactly
like your hook never firing; `src/mload.lisp` uses `*debug-io*` for its own
tracing for the same reason.

### The stale-image trap

**`make` can exit 0 while your file failed to compile**: SBCL's debugger
swallows the remaining stdin forms and EOF-exits 0, so every later test
exercises the **old** image. Check after every build:

```sh
test src/compar.lisp -nt src/binary-sbcl/maxima.core && echo 'EDIT NOT IN IMAGE'
```

Exactly `make`'s own dependency (`src/sbcl-depends.mk`:
`binary-sbcl/maxima.core : compar.lisp`).

**One-directional.** Source newer than core => the build definitely did not
finish. Core newer does **not** prove it was clean: a *semantic* error (calling
an undefined function) still writes a valid fasl, exits 0, loads, and the core
*is* redumped. For that, grep the build log for `caught ERROR`, `caught WARNING`
**and `undefined function:`** -- SBCL reports a call to a function that does not
exist as only a `caught STYLE-WARNING`.

`:lisp (fboundp 'maxima::my-new-fn)` is decisive **only for a newly added
function**; for an edited body it was already true and stays true after a failed
build -- test the behaviour instead.

Never run two builds concurrently; they share the fasl output directory.

## 5. Tests

All via `./maxima-local --no-init --batch-string='<call>;'`:

- `run_testsuite(tests=["rtest_abs"])` -- one file
- `run_testsuite()` -- the core suite
- `run_testsuite(share_tests=true)` -- core + share, what `make check` runs
- `run_testsuite(share_tests=only)` -- share only

Narrow to one file while iterating, but validate a finished change against the
**full suite, share tests included**: a core-only run skips the `share/` tests
(though core files `load()` share packages anyway), and only that run is long.
Green still proves nothing (below).

**Discard the first run when comparing timings or consing.** Share packages
compile into the runtime objdir on first use, so run one pays for that
compilation and allocates far more than run two, which only loads the fasls.
Correctness is unaffected, only the numbers move.

**Comparing two builds.** Alternate and repeat -- A, B, A, B, not all of A then
all of B: interleaving cancels drift from other load, and repetition shows the
noise floor. Add a targeted benchmark for whatever the change should most
affect, since a whole-suite time buries a large local win among thousands of
unrelated problems. Run the full suite regardless -- speed work still has to be
correct.

**Never `--very-quiet`/`--very-very-quiet` for tests.** They nil
`*display-labels-p*`, and `dim-mlabel` (`src/displa.lisp`) emits labels only
when it is true, so any test asserting on labelled output fails under them and
passes otherwise. **`--quiet` is fine.**

`$run_testsuite` takes further keywords (`src/mload.lisp`: `display_all`,
`time`, `debug`, ...). A share test named without `share_tests` warns
`is a share test, but share_tests was not set` and runs nothing.

### `batch(f, 'test)` is NOT `run_testsuite(tests=[f])`

A file with registered known failures reports every one of them under bare
`batch` and none under the suite, which tolerates them by number. Answers come
from the file only when `$batch_answers_from_file` is true -- `run_testsuite`
binds it and `--batch-string` forces it globally (`src/init-cl.lisp`) -- but it
is nil for `-b file` and interactive sessions, where the question goes to the
terminal; at EOF that problem fails with `RETRIEVE: End of file encountered.`,
and the answer left in the file shifts every later pair. **Never conclude "I
broke this" from bare `batch`.**

### The accounting rule

```
Running tests in <file>: P/P tests passed (not counting E expected errors)
No unexpected errors found out of N tests.
```

Per-file `P/P passed` **excludes** registered known failures; the headline
`out of N tests` **includes** them, so P + E = N. `make check` runs
`tests/<lisp>-test.sh`, a two-line wrapper for `tests/test.sh` generated from
`test.sh.in`, which greps the one `tests/<lisp>.log` it writes for exactly
**`No unexpected errors`** -- that string, not a failure count, is the pass/fail
contract. Edit `test.sh.in`; `tests/test.sh` and every `tests/*.log` are
generated and gitignored.

**Baseline before blaming your change.** The core suite is meant to be green,
core + share is not, so `make check` can be red before you touch anything, at
problem numbers no registry mentions. Nor is every share failure Maxima's:
results move between Lisp implementations and between versions of one, and the
older and less-used ones fail tests SBCL passes -- numeric printing is a
recurring culprit (`README-lisps.md` compares them). Record your own baseline,
build and Lisp before the change and compare against that.

### The known-failure registry

`src/testsuite.lisp` holds `$testsuite_files` and `$share_testsuite_files`.
**Two** entry formats parse (`expected-failures`, `src/mload.lisp`):

```lisp
"rtest_abs"                                               ; none
((mlist simp) "rtest_integrate" ((mlist simp) 826 827))   ; modern
((mlist) "rtest12" 68 69 70)                              ; legacy: bare numbers
```

Problem *N* = the *N*-th (input, expected) pair, `/* */` comments skipped.
Read-time conditionals (`#+gcl`, `#+allegro`, `#-sbcl`, ...) gate problem
numbers **and whole file entries**, so a file registered under one Lisp can be
absent under another, and numbers gated to a Lisp you are not running are
compiled out -- not yours. Fixing a bug prints
`Tests that were expected to fail but passed:` -- remove the entry in the same
commit, else `No unexpected errors` still prints and `make check` stays green on
a wrong registry.

### Writing tests

`tests/rtest_<topic>.mac`; share tests as `share/<pkg>/rtest_<pkg>.mac`.
Alternating pairs, input `;` / expected `$`. By convention the first pair kills
state (`tests/README.how-to` sec. 5; most files do it):

```maxima
(kill(all),0);
0$

abs(-x);
abs(x)$
```

- **Append, never insert.** Registry entries are *positional problem numbers*; a
  middle insertion re-points every later one -> a failure at the shifted number.
  `tests/README.how-to` sec. 9(d) suggests keeping known failures at the top so
  appends stay safe.
- **Leave the environment as you found it.** Some core files assert fact/context
  state at the end -- `[facts(), contexts]; [[], [initial, global]];`
  (`rtest16.mac`, `rtest_sign.mac`, both marked *"Leave this at the end of the
  file!"*) or separate `facts();`/`contexts;` checks. A leaked `assume` surfaces
  at the file's *highest* problem number. `forget`/ `remvalue`/`remfunction` at
  the end; prefer local option settings (`is(x<1), prederror:false;`).
- **Evaluation trap**: Maxima *evaluates* input, only *simplifies* expected
  output -- `makelist(sin(k*%pi),k,1,5);` / `makelist(0,k,1,5)$` fails. Write
  `''(makelist(0,k,1,5))$` or literal `[0,0,0,0,0]$`.
- **Answers go on the input line**, before the expected value; `retrieve` eats
  them off the file stream -- not problems. Asking twice needs two answers; a
  wrong count shifts the whole answer stream:

  ```maxima
  [asksign (foo), sign (foo), sign (foo)], ask_hide_prompt; p;
  [pos, pos, pos];
  ```

- **Bigfloat literals convert at READ time** with the ambient `fpprec`, not the
  one in force when the statement runs:
  `block([fpprec:30], is(abs(e - 1.56239406221731183021486562870b0) < 1b-25))`
  truncates to ~16 digits. Set `fpprec` in a previous statement.
- Cite the bug: `/* SF bug #NNNN */` (mostly a `tests/` convention; casing
  varies, so `grep -i`). A test whose answers run out prints its question and
  aborts the file with `batch: missing expected result in test script.`

**A green suite is not proof.** Several problems in `tests/rtest_integrate.mac`
are headed *"Expected failure"* (grep for the phrase) but **assert the wrong
answer** while no registry entry covers them, so they pass. Check such a header
against the registry before trusting a green run: fix rischint and tests written
that way turn red, and you may revert a correct fix.

**A test your change turns red may itself be wrong.** Read what it asserts
before reworking code, and ask whether the new result is only another form of
the same thing -- expanded against factored, or a reordering.
`ratsimp(new - old)` = 0 settles that for rational expressions; a nonzero
difference proves nothing, and `is(equal(a,b))` answers `unknown`, not `false`
(`trigreduce` sees `sin(2*x) = 2*sin(x)*cos(x)`, `ratsimp` and `trigsimp` do
not). When they agree, re-baseline the test -- its comment says why the old
value was chosen -- rather than contorting code to match it.

**Not in the suite**: `tests/testbench_*_manual.wxm` (visual, needs a human) and
`share/contrib/diffequations/tests/` (own harness).

## 6. Validating mathematical results

A `diff` round-trip does not validate an antiderivative -- both share the branch
error:

```maxima
I : integrate(%e^(x^3), x)$
diff(I, x);         /* gives %e^x^3 back -- looks perfect, proves nothing */
float(rectform(integrate(%e^(x^3), x, 0.5, 1.5)));  /* -2.8316-4.9046*%i */
quad_qags(%e^(x^3), x, 0.5, 1.5);   /* [5.6633, 3.1e-12, 21, 0] -- real */
```

The branch error here multiplies by a root of unity, so the magnitude survives
and only the phase moves: a plausible modulus is no comfort, and a real positive
integrand that comes back complex refutes itself. Cheap independent checks:

- `quad_qags` -> `[value, abserr, nevals, flag]`. Failure gives
  `[0.0, 0.0, 0, 6]`, which looks like zero; check flag and abserr.
- Bound the answer before trusting it -- sign, magnitude, monotonicity. An
  integrand in [1/3, 1/2] over length 8 must land in [8/3, 4], and a positive
  integrand cannot integrate negative; no reference value needed.
- Test a negative interval and one straddling zero; branch bugs show on one
  side.
- Substitute a returned root back in: `solve` can produce spurious ones.

## 9. Internal representation

```
((operator flag...) arg1 arg2 ...)
```

`(caar expr)` operator; `(cdr expr)` args. `simp` = already simplified, never
fabricate it. `array` = subscripted. Operators: `mplus`, `mtimes`, `mexpt`,
`mlist`, `mequal`, `mnctimes`, `mqapply`, `mrat`, `mdefine`, `mprog`, ...
Setting the global `simp:false` switches the simplifier off and many internal
routines then misbehave (`doc/info/Simplification.texi` says so), so a failure
under it is not a bug to chase.

```lisp
(meval '((mplus) 1 $x))  ; => ((MPLUS SIMP) 1 $X)
(add '$a '$b 1)          ; => ((MPLUS SIMP) 1 $A $B)
(ftake '%sin '$x)        ; => ((%SIN SIMP) $X)
```

**Use `alike1`, not `equal`.** `alike1` (`src/simp-utils.lisp`) is structural
equality, **ignoring every header flag except `array`** (`memqarr`); `equal`
gives silent false negatives on flag variants. `mrat`, `mpois` and `bigfloat`
headers take special branches -- a bigfloat's precision and decimal flag *are*
compared. `(alike1 '((f) $x) '((f simp) $x))` -> T;
`(alike1 '((f array) $x) '((f) $x))` -> NIL. `like` = `alike1` + `specrepcheck`
both sides, for CRE/Poisson; `assol` (`src/mutils.lisp`) = alist lookup by
`alike1`.

**Headers and plists are shared -- never mutate them.** The header cons in
`(cons '(mplus simp) args)` is a compile-time literal, so `nconc`/`rplacd` on
one car corrupts unrelated expressions. Plists share too (`src/nalgfa.lisp`:
`(setf (symbol-plist newvar) (symbol-plist var))`), so a per-symbol cache must
verify the symbol itself, not just a generation stamp.

**Booleans**: Maxima's `true`/`false` are exactly Lisp `T`/`NIL`, so a Lisp
predicate's `nil` comes back as `false`.

**Numbers.** `mnump` (`src/mutils.lisp`) covers Lisp numbers, `((rat) a b)`
**and** bigfloats; `ratnump` matches only `((rat) a b)`, not plain integers. An
`mnump` guard then `$float` is a **silent precision bug** (bigfloat -> double):
the `$scaled_bessel_i*` functions in `src/bessel.lisp`.

**CL rationals/complex are not Maxima's.** Maxima uses `((rat) a b)` (not CL
`1/2`) and `a+b*%i` over `$%i` (not `#C(a b)`). A raw CL object embeds silently
and even displays right, then fails later: `(ratnump 1/2)` -> NIL,
`float(x + #C(1 2))` -> `#C(1 2) is not of type REAL`.

**Bigfloats**: `((bigfloat simp <prec>) <mantissa> <exp>)` -- mantissa is a
**scaled binary integer**, not the digits; precision lives in the header. Test
`$bfloatp` (`src/simp-utils.lisp`, `:inline-impl t`) or `bigfloatp`
(`src/float.lisp`), which *returns* the value re-rounded to the current `fpprec`
-- use what it returns, not the argument. Raw Lisp arithmetic on a bigfloat is a
type error; house guard `(if ($bfloatp b) (minusp (cadr b)) (minusp b))`. Live
crash: `beta_incomplete_regularized` (`src/gamma.lisp`) applies `<=` to a
possible bigfloat (grep `"does not work for bigfloats"`). Two leaks: in
`(in-package #:bigfloat)` **unary `sqrt` skips contagion** -- no bigfloat
operand -> `cl:sqrt`, machine precision (rational -> *single* float); and
`integer-representation-p` (`src/numerical-utils.lisp`) is `-p`-named but
**returns the converted Lisp integer** (or nil) -- callers ignoring it keep the
original bigfloat.

**CRE**: `((mrat simp varlist genvar) numerator . denominator)`, e.g.
`($rat '((mplus) 1 ((mexpt) $x 2)))` ->
`((MRAT SIMP ($X) (#:G544)) (#:G544 2 1 0 1) . 1)` -- the gensym counter varies
per session; only the shape is stable. Sparse polynomial lists
`(var exp coef exp coef ...)`, **descending** powers; multivariate nest, main
variable by `pointergp`. Commentary atop **`src/ratmac.lisp`** explains `rat3*`.
Back with `ratdisrep`; `specrepcheck` handles CRE and Poisson.

**Symbol prefixes**: `$name` is Maxima-level and user-visible (`$sin`,
`$fpprec`); `%name` is the **noun** form (`%sin`, `%integrate`); `mname` is a
built-in operator (`mplus`, `mexpt`); `*name*` is a Lisp-only special
(`*expandp*`); a plain name is an internal helper with no Maxima-level name
(`simplifya`, `alike1`), reachable only as `?simplifya`. Verb/noun duality is
wired by `(get '$sin 'alias)` -> `%SIN`, `(get '%sin 'reversealias)` -> `$SIN`,
`(get '%sin 'operators)` -> `SIMP-%SIN` (the simplifier).

## 10. Code conventions

**`defmfun`** (`src/defmfun-check.lisp`) for anything user-callable -- the
overwhelming default; a handful of bare `(defun $...)` survive as legacy. `$`
names get an arg-count wrapper, `FOO-IMPL` (the body), and
`arg-list`/`impl-name`/`translated` properties; hence `sin(1,2)` ->
`sin(y): expected exactly 1 arguments but got 2: [1, 2]`. Options
`:properties ((evfun t))`, `:deprecated-p $bar`, `:inline-impl t`, as in
`(defmfun ($foo :properties ((evfun t))) ...)`. Plain `defun`: internal helpers.

**`defmvar`** (`src/globals.lisp`) for option variables; bare `(defvar $...)` is
legacy. Its docstring becomes the Lisp `defvar` docstring and reaches no user --
user-visible text lives in `doc/info/` (sec. 14). `fixnum`/`string`/`flonum`
**validate nothing** (deprecation warning only): a `fixnum` variable accepts a
string. **`boolean` is not ignored** -- its clause installs an `assign`
restricting values to `t`/`nil`: `ifactor_verbose:"hello";` gives ``assignment:
cannot assign `hello' to `ifactor_verbose': ...``. Real validation:
`:setting-predicate`, `:setting-list`, `:setter-method`,
`:properties ((assign ...))` -- compile-time error combining an `assign`
property with `:setting-predicate`/`:setting-list`, or `boolean` with any of
those three. A `Deprecated defmvar option` warning fires at **macroexpansion**:
during `make` for `src/`, but on every `load` of a share `.lisp` shipped as
source (`load(simplex)`); suppress with `*warn-deprecated-defmvar-options*` =
nil. Multi-file variables go in **`src/globals.lisp`**; compilers coalesce equal
constant lists and Maxima mutates some -- use fresh conses.

**Declare specials before you bind them.** A `let` on a special `defvar`'d
*later* in the same file binds **lexically** and does nothing. SBCL warns only
for `*foo*`-shaped names; most Maxima specials are earmuff-free (`varlist`,
`genvar`, `errcatch`, `$errormsg`), so it compiles silently.

**`def-simplifier`** (body e.g.
`(cond ((float-numerical-eval-p x y) ...) (t (give-up)))`) sets
noun/verb/alias/reversealias + `operators` and binds local `give-up`; `form`,
`%%simpflag` visible in body. Subscripted:
`(def-simplifier (li :subfun-arglist (s)) (x) ...)` -> `specsimp`.

**`defmspec`** (`src/maxmac.lisp`) for args that must **not** be evaluated
(`$declare`, `$assume`, `$buildq`, ...). Body gets raw forms, `meval`s
selectively.

**Building expressions** -- never hand-cons (`src/mopers.lisp`,
`src/opers.lisp`): `add`, `mul`, `div`, `power`, `inv`, `neg`, `sub`;
`take '(%sin) x` / `ftake '%sin x` apply+simplify; `fapply`, `mfuncall`; starred
forms (`add*`, `take*`, ...) when args are **not yet simplified**, unstarred
assume they are; `simplifya` (`simplify` = `(simplifya x nil)`), `resimplify`,
`meval`.

**Errors**: `(merror (intl:gettext "foo: argument must be a list; found ~M") x)`
-- nearly every `merror` in `src/` wraps its format string in `intl:gettext`; do
the same (catalogs in `locale/`). `~M` and kin are **`mformat` directives**, not
CL `format`, and work only inside `merror`, `mtell`, `mformat` and friends: `~M`
= 2-D display (`displaf`), `~:M` = 1-D/`grind` form (`mstring`), `~@M` =
operator name (the `op` property). Output/warnings: `mtell`/`$print`, not
`format t`.

**No `:test #'eq` on symbols.** `member`'s default `eql` is already `eq` for
symbols, so the keyword adds nothing when the item is a literal symbol or the
list a literal list of symbols -- and it silently narrows the test if a float or
bignum ever joins the list.

**Naming.** Maxima: `write_long_names_like_this`, not camelCase or
runtogetherwords. Lisp: lowercase, hyphenated, `*earmuffs*` for specials; `$` is
Maxima's namespace -- never add a `$` symbol not meant to be user-visible.

**Edit minimally.** Make the smallest change that fixes the problem, matching
the surrounding style even where it is poor: do not reindent, rewrap, rename or
refactor code you are not fixing. A tight diff is reviewable and cherry-picks
cleanly between release branches (sec. 15); a tidied one buries the fix and
collides with everyone else. **Tabs are load-bearing** -- nearly every top-level
`src/*.lisp` contains literal tabs (Emacs 8-column convention), so an editor
that normalizes whitespace turns a 3-line fix into a sprawling one. Preserve
them where they are, but indent a function you write from scratch with spaces.
`#+`/`#-` per-Lisp workarounds: add narrowly, comment why. `#+nil`/`#+broken`
disable code in place -- grep hits inside aren't live.

**Comments.** Describe what the code does now. Never narrate history ("this used
to...", "I changed...") -- that is the commit message's job. Existing comments
do it anyway, often in the first person: read them as archaeology, not spec.
Write Lisp names in ALL-UPPERCASE (`SIMPLIFYA`, `MEVAL`) and Maxima names
exactly as they are (`display2d`, `%sin`) -- Maxima is case-sensitive, the Lisp
reader upcases; same convention in commit messages. **Wrap at 80 columns**, code
and comments alike, unless the surrounding code already runs wider or nesting
makes it infeasible -- nearly all `src/*.lisp` lines already fit (tabs at 8).

## 11. Subsystem notes

**Sign** (`src/compar.lisp`, `src/db.lisp`) -- `sign`/`minus`/`odds`/`evens` are
one answer in four specials, set together; `$asksign`/`$sign` rebind those four
plus `factored` (`signfactor`'s re-entry guard), so a handler setting only
`sign` leaks the others. `sign-mtimes` does `nconc odds o` -- pass fresh conses.
`signsum` stops at `$pnz`. The fact DB keys on the `data` property (`dinternp`
returns the symbol for atoms; `dcomp` treats no-node and empty-node alike as
`$pnz`; `(get sym 'data)` = does the DB know anything). `$assume_pos` upgrades
unknown *mapatoms* only -- `f(y)` needs `$assume_pos_pred`. `*local-signs*`
holds answers asked *of the user*, not computed signs. Asking goes via
`$asksign` (`asksign01`, `ensure-sign`, ...); `radmabs` (`src/simp.lisp`) asks
when `(and limitp (free e '$%i))`, from `simpexpt`. `meval*` (`src/suprv1.lisp`)
-> `with-top-level-environment` -> `clearsign`: asksign facts die between inputs
while `assume`s survive, and they are stored *reduced* --
`(asksign(asin(x)), facts())` in one input gives `x > 0`.

**Limits** (`src/limit.lisp`) -- vocabulary `inf`, `minf`, `infinity`, `ind`,
`und`, `zeroa`, `zerob` (`extended-real-p`); no directed infinity. `extra-simp`
is top-down, so match a subexpression shape only after simplifying it. Guard
`$csign` re-entry (`$csign -> sign -> $limit -> extra-simp -> $csign`). `getexp`
calls `ask-integer` on exponents free of the limit variable, so rewriting
`%e^(3*log(x)/sigma^2)` to `x^(3/sigma^2)` asks *"Is 3/sigma^2 an integer?"* and
hangs batches. `var`/`val` are special; `var` is pre-shifted to zero and
uninterned, so `boundp` misses a stale `var`.

**Rpart/integrator** (`src/rpart.lisp`, `src/risch.lisp`) -- `absarg` is correct
only mod `2*%pi`; only `$carg` and `risplit`'s `%log` may reduce, because
`risplit-expt` needs it unreduced. Canary `integrate(sqrt(1-cos(t)),t,0,2*%pi)`
-> `2^(5/2)` (`tests/rtestint.mac`); `-2^(5/2)` means you over-reduced.
`domain:real`+`radexpand:true` gives `(-8)^(1/3)` = `-2`, but `gamma_incomplete`
is principal-branch -- producer and consumer must agree, and integer exponents
keep distributing. `atan2(y,0)` is legitimate; test the zero-second-arg case.
`implicit-real` (bound by `rischint`, read by `absarg1`) answers signs
positively so the integrator never interrogates the user: it looks dead but
disabling it hangs `rtest16`, and any unattended batch. `rischp`
(`src/globals.lisp`) is the same pattern. `sdiffgrad` (`src/comm.lisp`) calls a
functional `defgrad` derivative with the actual args, then `$psubstitute`s
placeholders -> actuals, so an already-substituted lambda result is substituted
twice and captures colliding user symbols -- return `#$...$` templates in
placeholder names.

## 12. Do not trust the comments

`TODO`/`FIXME`/`XXX`/`HACK` markers are scattered through `src/` (grep
case-insensitively; most lowercase hits are prose, not markers), and the code
under them has moved on. Comments here are decades old and go stale in both
directions: one asserts a case is handled when it is not, the next warns that
something cannot work when it now does. A `FIXME` may sit directly above the fix
that silenced it; a comment saying a function is "never called with X" may be
right for a reason it does not give. Read them as archaeology, not specification
(sec. 10).

> **Rule: build and reproduce before acting on a comment** -- whether it
> promises you the code works or warns you that it does not.

## 13. Adding or removing files

**`src/`** -- `src/maxima.system` (`:module`) and `src/maxima.asd`, which names
every file. `src/Makefile.am` needs no edit: it globs `$(srcdir)/*.lisp` plus
`numerical/` and `numerical/slatec/` -- only a new *subdirectory* needs one.
Never hand-edit `src/*-depends.mk`.

**`tests/`** -- `$testsuite_files` (`src/testsuite.lisp`) only;
`tests/Makefile.am` globs `*.mac`; adding to an existing file needs neither
(sec. 5).

**`share/`** -- `share/my_package/my_package.lisp`|`.mac`;
`rtest_my_package.mac` -> `$share_testsuite_files`; `doc/info/my_package.texi`
-> `doc/info/Makefile.am` + `doc/info/include-maxima.texi.in`, starting from
`share/template.texi`. `share/Makefile.am` `find`s every file, so it needs no
list -- but a package with its own `Makefile.am` goes in both `AC_CONFIG_FILES`
(`configure.ac`) and `SUBDIRS` (`share/Makefile.am`:
`contrib logic draw nelder_mead raddenest`). A Lisp-heavy package gets a
`my_package.system` loaded by a Lisp stub calling `mk:oos`.

After any of these: rebuild (sec. 2), then the full suite (sec. 5);
`make install` catches `Makefile.am` mistakes `make` misses.

## 15. Project workflow

Upstream SourceForge: scratch branch -> `master` -> push there
(`README.developers-howto` sec. 1). Release branches are `branch-5_mm`, tags
`5.mm.0` and on, the tag matching `configure.ac`. A fix belongs with a test
appended to the matching `tests/rtest_*.mac` in its idiom, never a new file.
Commits: short subject + explanatory body naming the functions touched, wrapped
near 72 columns --
`forget(), remove(), killcontext(): make return values more useful`. That width
is the prevailing habit, not a documented rule.

**`ChangeLog`** (top level) collects the cycle's entries under underlined
headings; add your line under the one that fits. The set is per cycle, not fixed
-- read the `ChangeLog` you are committing against rather than assuming last
cycle's headings. **`changelogs/ChangeLog-5.mm.md` is a release-time artifact**,
hand-written per release from `git log branch-5_<mm-1>-base..HEAD` --
underscore: that is how `README.developers-howto` sec. 9.5 creates the tag,
though its sec. 9.3 prints the command with a dot. Never append it in a feature
commit.

**Changing SBCL version requires `make clean`.** `src/binary-sbcl/` is not
version-scoped and fasls lock to the exact implementation version string --
`sb-fasl:+fasl-file-version+` can be identical across releases, so it is no
guide. `defsystem` recompiles by timestamp, never by fasl version, so stale
fasls load and the build dies with
`is a fasl file compiled with SBCL ..., and can't be loaded into SBCL ...`.
`clean-sbcl` (`src/Makefile.am`) `rm -rf`s the `binary-sbcl` directories. Re-run
`./configure` only if the Lisp's *name* changes: `src/maxima.in` execs
`"@SBCL_NAME@"` (default `sbcl`) with `--core`, so a PATH swap needs none,
whereas `--with-sbcl=<path>` bakes the path in.

**Check the checkout before doing archaeology**: in a shallow clone
(`test -f .git/shallow`) nearly every line blames to the boundary commit with a
leading `^`, so **`git blame` and `git log -S` are useless**; never call a line
recent on that evidence.
