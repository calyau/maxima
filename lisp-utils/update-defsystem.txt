lisp-utils/mk-defsystem.lisp is MK:DEFSYSTEM exactly as its maintainers
publish it (see its header). Never edit it. Maxima loads it through
lisp-utils/defsystem.lisp, which adds Maxima's changes from outside, by
wrapping a few upstream functions:

- Once a file is recompiled, every file compiled after it is recompiled
  too, declared dependency or not.
- A binary that fails to load is deleted, recompiled and loaded once more.
- OPERATE-ON-SYSTEM keeps the caller's *LOAD-VERBOSE* and
  *COMPILE-VERBOSE*, and the banner upstream prints while loading is
  suppressed.
- After compiling a file that grew the heap a lot, SBCL and CMUCL collect
  garbage.
- On Windows, files and binary directories keep their drive letter
  instead of getting the current one.
- Portability fixes for ECL, CLISP and GCL 2.6 and 2.7.

Both files are installed through genericdirDATA in
lisp-utils/Makefile.am, and src/Makefile.am copies both into binary-ecl
and binary-abcl, where ABCL, and ECL on Windows, load them at every
start. The Windows installer packages what make install installs, so it
needs no list of its own. A file added to lisp-utils has to go into the
same places.

Report bugs in MK:DEFSYSTEM itself to its maintainers, so that the
wrapper can shrink.

To upgrade MK:DEFSYSTEM:

1) Replace lisp-utils/mk-defsystem.lisp with the new upstream file.

2) Set *TESTED-VERSION* in lisp-utils/defsystem.lisp to the new
   MK::*DEFSYSTEM-VERSION*. Until then, loading it warns.

3) Run lisp-utils/test-defsystem.lisp with every Lisp at hand, for example

     sbcl --non-interactive --load lisp-utils/test-defsystem.lisp

   Every check must pass. A failure, or a warning that a wrapped function
   is missing, means the new version changed something the wrapper relies
   on. Fix lisp-utils/defsystem.lisp, not mk-defsystem.lisp.

4) Build Maxima with every Lisp at hand and run its test suite.
